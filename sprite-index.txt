  What works fine on GitHub Pages

  Everything that's "data + UI" is straightforward:

  - Backup/restore — export your progress as a JSON file so you can move it
  between phone and PC, since localStorage doesn't sync on its own

  The hard part: Epic sync

  This is the one thing GitHub Pages cannot do, and it's worth understanding why
  before you plan around it:

  1. GitHub Pages serves static files only — no server code. Epic's OAuth
  requires exchanging a code for a token using a client secret, which must never
  sit in front-end JS (anyone could view-source it).
  2. Epic has no public, documented "list this account's cosmetics" API. Fan
  sites hit internal Fortnite endpoints, which requires a server proxy anyway
  (browsers block cross-origin calls without permission).

  So: sites like spritetrading.com have a backend. That's also probably why
  their index "somewhat works and doesn't" — unofficial endpoints break
  constantly.

  Two ways around it:

  - Manual tracking (recommended to start). You tap sprites to mark
  collected/mastered. Sounds tedious, but it's a one-time pass, it never breaks,
  it costs nothing, and it works offline. Honestly this is the more reliable
  product.
  - Add sync later. Keep the site on GitHub Pages, and put just the Epic auth +
  lookup on a free serverless function (Cloudflare Workers has a generous free
  tier). The front end doesn't change — sync just becomes an optional "import my
  account" button. You can build phase 1 now and bolt this on if you still want
  it.

  The other real question is where the sprite data comes from — names, rarities,
  drop rates, effects. That list has to exist somewhere before the UI means
  anything.
